# Авторизация

Авторизация идёт после аутентификации. Она отвечает, может ли этот вызывающий выполнить действие над объектом, полем, связью или контекстом.

mxHeadless складывает четыре слоя:

1. **Право маршрута** (например `resources.read`)
2. **Scope API key** (те же строки, что и permissions)
3. **ACL MODX** (`hasPermission`, доступ к контексту, `view` ресурса)
4. **Политика полей** (hidden и protected)

Должны пройти все слои. API key с `resources.read` не поможет, если связанный пользователь MODX не видит ресурс в выбранном контексте.

## Публичные и привилегированные маршруты

Маршруты с `public: true` допускают anonymous read, если это разрешено в определении объекта. Мутации для anonymous недоступны.

| Группа | Кто вызывает | Кэш |
|--------|--------------|-----|
| Чтение контента | Anonymous, сессия, key | Публичный GET |
| Мутации | Сессия или key со scope | `private, no-store` |

## Видимость полей

| Политика | Поведение |
|----------|-----------|
| Hidden | Не попадает в SELECT и в JSON |
| Protected | Нет в ответе без отдельного права на поле |
| Обычное | В ответе при разрешении и в `fields` |

## Preview

`?preview=true` требует `view_unpublished` (сессия) или scope `preview` (key). Anonymous preview всегда 403 или 404 по политике.

## 403 и 404

Если факт существования ресурса нельзя раскрывать, API отдаёт 404 вместо 403.
